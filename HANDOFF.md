## 1. What we are building

**FM Condition Survey** — a facilities-management building condition/defect
survey app for **OCS**, used to survey the **Abu Dhabi Equestrian Club**.

A surveyor walks a site, records defects ("snags") against locations with
department, priority (P1–P4), estimated cost in AED, and photos; captures GPS;
and produces client-facing **PDF** and **Excel** reports.

It runs as:
- a **web app** (React + Vite on Vercel)
- an **Android APK** (same bundle wrapped in Capacitor), updated **over the
  air** without reinstalling

It is **offline-first**. A surveyor with no signal must be able to do a full
inspection; everything syncs to Supabase when connectivity returns. Nearly
every hard bug in this project has come from breaking that promise.

**Hierarchy (enforced):** `Project → Facility → Survey Items / Sign-Off / Reports`

- Web: https://fm-condition-survey-data-source.vercel.app

### Database changes made this session
Applied as migrations against the live project:

1. **`projects` table** — `project_number` is generated by a Postgres
   **sequence as a column DEFAULT** plus a unique index. The browser never
   picks a number, so two devices creating a project simultaneously cannot
   collide. Verified: a deliberate duplicate insert was rejected.
2. **`condition_surveys.project_id`** — nullable FK to `projects`. Nullable on
   purpose: a device still running an older bundle keeps pushing facilities
   with no project, and refusing those would lose a surveyor's work.
3. **Existing data migrated** — all facilities attached to `PRJ-0001`. Only
   `project_id` was written; no survey, snag or photo was touched.
4. **`fm_survey_users`** — app user profiles with `role` (`admin`/`user`).
   **Named `fm_survey_users`, NOT `profiles`**: this Supabase project is shared
   with an unrelated CAFM system that already owns tables called `profiles`,
   `user_credentials`, `work_orders`, `buildings` etc. **Never touch those.**
5. **`fm_is_admin()`** — `security definer` helper so the RLS policy on
   `fm_survey_users` can check the caller's role without recursing into itself.
6. **Edge Function `admin-users`** — the only thing that can create or delete a
   login. Holds the service-role key server-side; it never reaches the browser.

## 5. Important technical decisions

### Navigation is a view state, not a router
`App.jsx` holds `view`, one of: `projects` | `facilities` | `survey` |
`reports` | `users`. The app is wrapped in Capacitor and has never had URL
routing; adding history and deep links would introduce a class of problems for
no gain on a device. **Don't add react-router without a concrete reason.**

### The app always opens on Projects
It remembers the last project so re-opening it is one tap, but **never
auto-advances past the project screen.** Auto-continuing defeated the point of
having a hierarchy and dropped users into a blank facility.

### Sidebar is desktop-only (`hidden lg:flex`)
The mobile flow (bottom tab bar, single column) is the tested day-to-day path
for a surveyor on site. The sidebar is an additional way in on a wide screen,
**not a replacement**. Below `lg` the OCS logo falls back into the header.

### Hub screens are full-width; survey screens stay capped
Projects/Facilities/Reports/Users fill the viewport. The **survey view keeps
`max-w-6xl`** — form fields spanning a 2560px monitor would be worse, not
better. There are 5 `<main>` containers in `App.jsx`; the last one is the
survey view and is deliberately different.

### Auth model: "login once, then works offline"
`persistSession: true` in `supabaseClient.js` is **load-bearing** — a surveyor
signs in on wifi and that session must survive app restarts in a dead zone.
Setting it back to `false` breaks the core offline promise.

### Only the server decides who may create users
`admin-users` runs with `verify_jwt: false` **and authenticates by hand**,
because it must also handle the very first admin when no session exists to
present a JWT. Bootstrap only works while `fm_survey_users` is empty and only
ever makes that first account an admin. Verified closed immediately after use:
a second unauthenticated attempt was refused with 403.

### Notification badge shows real data
The reference design had a red "3". The bell shows the genuine count of work
still waiting to upload. **Don't hardcode a decorative number.**

### Reports shortcut only appears while surveying
Reports need a facility behind them; on the hub screens it pointed at nothing.

### Things that must not be reverted
- `pushSurvey()`'s **upsert + tombstone** model in `cloudSync.js` — reverting
  to delete-and-reinsert has destroyed real user data **twice**.
- The Supabase **mass-delete-block trigger**. Note: `DATA_SAFETY.md` says it
  blocks statements deleting *more than* 5 rows, but **observed behaviour is
  that a 5-row delete is also rolled back** — batch in 4s or fewer. This is
  not yet fixed in the app's own `deleteSurveyPermanently()`, which batches
  in 5s (see §7).
- **Tab panels stay mounted** (`hidden`, not conditional render) in `TabPanel`.
- `notifyAppReady()` in `otaUpdates.js` — removing it breaks OTA rollback.
- `pt-1`, never `py-1`, on the mobile bottom nav — a `py` utility overrides
  `.safe-area-pb` from the components layer and puts the tabs under the
  Android navigation bar.
- Read `var(--safe-area-inset-*)` **before** `env(safe-area-inset-*)` —
  `env()` returns 0 on Android WebView below v140.

## 7. Current bugs / issues

### Open
1. **Delete-facility batching is off by one.** `deleteSurveyPermanently()` in
   `cloudSync.js` batches deletes in **5s**, but the database trigger appears
   to reject at 5, not above 5. **Deleting a facility with 5+ snags will
   silently fail.** Change the batch size to 4 and correct `DATA_SAFETY.md`.
   This was observed directly while cleaning up test rows.
2. **RLS on survey tables is still open to the anon key.** Login gates the
   *app*, but `projects`, `condition_surveys`, `survey_items`, `survey_photos`
   still grant full access to `anon`. Anyone with the URL and the public key
   could read/write around the app. Deliberately left alone: tightening it
   locks out every device that has not yet updated **and** signed in.
   Do this once all devices are on the new build.
3. **`fetchLatestSurveyId()` fallback is questionable.** On a device with no
   local survey, startup adopts *the most recently updated survey across the
   entire account*, ignoring projects. Pre-existing behaviour, not yet
   reviewed against the new hierarchy.
4. **`syncQueue.js` is dead code.** Nothing imports it. `CLAUDE.md` describes
   it as the durable offline queue; it isn't wired up. The real mechanism is
   `pendingSync` flags + `flushPendingSurveys()`.
5. **`test_verify.js`** at the root imports a deleted file and will throw. Not
   part of any build.

### Never verified on a physical Android device

- Native GPS capture end-to-end
- A real airplane-mode → reconnect cycle
- The safe-area fix by eye on the phone

## 8. What was tried and failed

**Read this section before repeating any of it.**

### Testing against production — twice caused real problems
- Browser automation was pointed at the **live** Supabase while verifying the
  login flow. Signing in on a fresh session auto-created and pushed **three
  blank facilities** (FAC-021/022/023) into the user's live project. They were
  later deleted with permission, and the root cause was fixed (§below).
- Worse: after seeing snags missing, a **blanket
  `restore_deleted_items(...)` over a 6-hour window** was run. The deletions
  had actually been the *user's own*, so this **resurrected 9 snags and 7
  photos they had deliberately removed**. Cleaning it up took several rounds.
  **Lesson: query the database to establish ground truth before "fixing"
  anything, and never run a blanket restore — target specific rows.**

**Use `.env.mock` (`npx vite build --mode mock`) for anything interactive.**
It points at `http://localhost:4199`. A local mock lives at
`C:\Users\SAIF412\AppData\Local\Temp\claude\mock-supabase.mjs` and now
implements minimal GoTrue endpoints so the login gate can be exercised without
production. Always confirm the build is isolated:
```bash
grep -l "yymyqygpyxbndifrgjvo" dist/assets/*.js && echo "ABORT" || echo "SAFE"
```

### Fixes that looked right but were not the real cause
- **"Item disappears after a second"** — first assumed a sync bug. It was the
  realtime handler adopting the server's own echo of an unfinished push.
- **"Phone shows 3 snags, laptop shows 1"** — assumed a sync fault. It was
  **two entirely different survey records**, both with blank names so both
  displayed as "Unnamed facility". Not a bug at all.
- **Blank facility pushed on reconnect** — a one-shot `skipCloudPushRef` flag
  was *supposed* to suppress it, but only the debounced autosave checked it;
  the reconnect handler called `pushAndSettle()` directly and never did.
  Replaced with a content check (`surveyIsWorthSyncing`) so **every** caller is
  safe by construction. A timing flag racing across two effects is fragile.
- **Work lost between restarts** — `lastKnownRevision` in `storage.js` was a
  **single number shared by every survey**. Switching facility made saves look
  like a conflict, so they were silently refused *forever* for that facility.
  Now a `Map` keyed by survey id.
- **Excel missing photos** — the register only ever embedded `photos[0]`.
  Removing the "Photo Evidence Log" sheet (at the user's request) removed the
  only place photos 2, 3, 4… appeared. Now one column per photo.

### Environment gotchas
- `pkill -f mock-supabase` **does not work** from Git Bash against Windows node
  processes. A stale mock server survived a whole day and served old code.
  Kill by PID: `Get-NetTCPConnection -LocalPort 4199 -State Listen` →
  `Stop-Process -Id <pid> -Force`.
- Bash heredocs break on JSX template literals. Write a `.py` file and run it.
- `npm run android:build` fails under Git Bash. Use:
  ```bash
  export JAVA_HOME="C:/Program Files/Eclipse Adoptium/jdk-21.0.12.101-hotspot"
  export ANDROID_HOME="C:/Users/SAIF412/AppData/Local/Android/Sdk"
  npx vite build && npx cap sync android
  cd android && ./gradlew.bat assembleDebug
  ```
- `w-4.5` / `h-4.5` are **not** real Tailwind classes here (no custom spacing
  scale) — they silently do nothing.
- The preview pane is often ~533px wide, so desktop screenshots come back
  zoomed or time out. Measure with `javascript_tool` instead of trusting them.
- Destructive SQL is sometimes blocked by the safety classifier. Don't retry
  repeatedly to slip past it — ask the user.
